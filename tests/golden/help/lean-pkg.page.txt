usage: lean-pkg page [-h] [--write] [--check] [--out PATH] [--site DIR] [--html PATH] [--repo DIR]
                     [--strict-preview] [--corroborate] [--attested] [--trusted-root FILE]
                     [--allow-private-manuscript] [--agent AGENT] [--json]
                     name

positional arguments:
  name

options:
  -h, --help            show this help message and exit
  --write               replace the marked block in the package README.md (append it when absent);
                        prose outside the markers is untouched. For a gated package without lean-
                        pkg-binding.yaml at the gated commit it then keeps the receipts bound
                        through the deprecated registry route (when the record says nothing:
                        `update NAME --accept-docs-descendants`, its own registry write; a record
                        false is left alone), with a WARN, and writes lean-pkg-binding.yaml into
                        the working tree (never staged or overwritten) to commit before the next
                        verify run
  --check               exit 1 when the README block is missing or stale, the lean-pkg credit is
                        missing, or a site sentence has no backing receipt (or, for GitHub
                        Actions, no corroborated run: --corroborate); with --site/--html also when
                        those files are missing or stale; writes nothing
  --out PATH            write the block here instead; README untouched
  --site DIR            also write DIR/verification.md (the full page) and DIR/coverage.md (every
                        row, its claims, inputs and notes) for MkDocs; with --check, compare them
                        instead
  --html PATH           also write one static HTML file (no script, no external asset) from the
                        same data; with --check, compare it instead
  --repo DIR            read the checkout DIR instead of the registered local_path, for this call
                        only (never saved; for CI): DIR must be a git work tree, and when it has
                        remotes one must be the package's repo; not with --write. Its committed
                        HEAD is read: when the recorded gate receipt does not bind that HEAD (or
                        an evidence-only descendant), the links and Lean statements are read at
                        HEAD, no receipt fact is shown and the page says so; with --check,
                        differences of such a preview from the receipt-bound files are warnings
                        (exit 0)
  --strict-preview      with --check --repo: a preview's differences from the receipt-bound README
                        block and --site/--html files fail the check (exit 1) instead of warning
  --corroborate         ask the public GitHub REST API about each GitHub Actions job coverage.yaml
                        lists (level 2: the run, its job, the pinned verify.yml, the receipt
                        annotation), and render the GitHub Actions sentence, with its run links,
                        only when every one reaches it; a failure is named and fails closed.
                        GH_TOKEN or GITHUB_TOKEN, when set, only raises the rate limit and is
                        never printed
  --attested            verify each GitHub Actions job coverage.yaml lists at level 3: its
                        committed Sigstore bundle (ci.attestation) with `gh attestation verify`,
                        an optional outside tool, and the certificate against the ci block; the
                        sentence renders at level 3, which holds after the run's records expire
                        (with --corroborate too, level 2 must also hold); a failure is named
  --trusted-root FILE   with --attested: verify offline against this Sigstore trusted root (gh
                        attestation verify --custom-trusted-root)
  --allow-private-manuscript
                        render against manuscript.version 'unposted'; the page then says so
  --agent AGENT         with --write: the lease holder, when the package is leased
  --json                machine-readable JSON on stdout
