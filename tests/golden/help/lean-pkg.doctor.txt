usage: lean-pkg doctor [-h] [--fetch] [--package NAME] [--upgrade-from OLD] [--to NEW]
                       [--source DIR] [--json]
                       [NAME]

positional arguments:
  NAME                also check this package's committed lean-toolchain, Mathlib commit (lake-
                      manifest.json) and recorded comparator receipt's tool digests against the
                      LTS stack its coverage.yaml declares (`stack: NAME`; docs/stacks/): a warn
                      line on a mismatch or a stack past its window, never an exit 1

options:
  -h, --help          show this help message and exit
  --fetch             git fetch origin in the tool checkout and the registry repo before comparing
                      (default: local refs)
  --package NAME      also compare the lean-pkg that wrote each gate receipt of package NAME (the
                      receipt's producer.lean_pkg) with the running one: a `producer <role>` warn
                      line on a skew across a breaking change to receipts, gate or claims, naming
                      the upgrade-record entries and the `doctor --upgrade-from` command, or on a
                      newer producer; never an exit 1. --json adds producer_skew
  --upgrade-from OLD  instead of the diagnostics: what changed for a package author since OLD (a
                      version, 0.9.0 / v0.9.0, or any commit of the lean-pkg repository): formats,
                      on-disk keys, commands, flags, --json keys, aliases, Python floor, packaged
                      files, and the curated behaviour changes of docs/upgrades/; read-only
                      (docs/design/upgrade-preflight.md)
  --to NEW            with --upgrade-from: the newer version or commit (default HEAD of the
                      source)
  --source DIR        with --upgrade-from: the lean-pkg git checkout to read both trees from
                      (default: the checkout this lean-pkg runs from)
  --json              machine-readable JSON on stdout
