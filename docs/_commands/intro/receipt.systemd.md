| `receipt systemd` | the same receipt from a finished systemd --user service unit, for checks run locally in a capped unit; reads and writes no registry. The unit's terminal state comes from one of: `--run -- CMD ...` (lean-pkg starts CMD as the transient unit `U` with `systemd-run --user --unit=U -p RemainAfterExit=yes -p WorkingDirectory=<repo> -p OOMPolicy=stop -p MemoryMax=8G -p MemorySwapMax=0 -p CPUQuota=400% -p RuntimeMaxSec=4h` (`--memory-max`, `--memory-swap-max`, `--cpu-quota`, `--runtime-max` change the caps; a value must be finite), the unit's stdout and stderr going to `--stdout` / `--stderr`, `PATH` and every `--setenv NAME=VALUE` passed; `--require-tools A,B,...` (repeatable) first resolves each project-declared executable with `type -P` in the unit's `PATH` before the unit is created, prints each resolved path, real path and SHA-256 to stderr (`--json` `run_tools` {required, resolved[] {name, path, realpath, sha256}, missing}) and refuses, running nothing, when one is missing; RemainAfterExit keeps the finished unit loaded, so lean-pkg polls `systemctl --user show U` until it is terminal, captures its properties and this host's name to `--properties-out` (default `<log>.unit.properties`, kept even when the receipt is refused) and only then stops and resets the unit; `--log`, `--stdout`, `--stderr` must not exist yet, and the checkout must be at `--commit` with no tracked change and no untracked file under the package directory before the run and still after it; untracked means listed by `git ls-files --others --exclude-standard`, less `.lean-receipts/`, `.lake/` and the run's own output files; files git ignores are not checked, so they are not bound), `--properties-file F` (`systemctl --user show U -p Id,LoadState,ActiveState,SubState,Result,InvocationID,ExecMainCode,ExecMainStatus,ExecMainStartTimestamp,ExecMainExitTimestamp,ExecMainStartTimestampMonotonic,ExecMainExitTimestampMonotonic,NRestarts,MemoryPeak,CPUUsageNSec,MemoryMax,MemorySwapMax,CPUQuotaPerSecUSec,RuntimeMaxUSec,OOMPolicy,RemainAfterExit` saved before the unit was collected, plus a `Hostname=` line for the host it ran on; exactly these properties are read, `RemainAfterExit` and the resource ones optional, so a capture without `RemainAfterExit` stays valid; `MainPID` is not exported), else `systemctl --user show U` now on this host. Unit checks (every failure listed, any one refuses: exit 1, nothing written to `.lean-receipts`): `LoadState=loaded` (a `--collect` unit read after it finished is not found), `Id` is U (`.service` added), a 32-hex `InvocationID`, terminal (`ActiveState` `failed` or `inactive`, or `active` with `SubState=exited`; `activating`, `running`, `deactivating` refuse) with an exited main process, `Result=success` (`oom-kill`, `timeout`, `signal`, `core-dump`, `exit-code` are named), `ExecMainCode` exited with `ExecMainStatus` 0 (killed or dumped: the signal is named), `NRestarts` 0, a host name. Then every `receipt slurm` check: the stdout seal or the in-log fallback, an optional stdout `invocation-id` line equal to the InvocationID, an empty `--stderr`, the toolchain, Mathlib rev, sorry count, axioms, checker and the optional `commit:`, `job-id:` (the job_id or the InvocationID), `generated-at:` lines, and the public-safety scan after redacting the checkout's absolute path to `<repo>`, `$HOME` to `<HOME>`, `/run/user/N/` to `/run/user/<UID>/` and every `--redact`. `job_id` is `systemd-user:<U>:<InvocationID>@<host label>`, the label being `h-` and the first 12 hex digits of the SHA-256 of the lower-cased host name (the running system's, or the `Hostname=` line's); the host name itself is never written. Writes, beside the receipt and the redacted log, `<c12>-<slug>-unit.properties` (the recognised properties only, in a fixed order, host last as its label; its SHA-256 is the additive receipt key `unit_properties_sha256`), and prints the README entry (unit, invocation, host, Result, exit, runtime, CPU, memory peak, the caps, a `- Unit properties:` line). `--json` as `receipt slurm` with `unit` {id, invocation_id, host, active_state, sub_state, result, exec_main_code, exec_main_status, runtime_usec, cpu_usage_nsec, memory_peak, memory_max, memory_swap_max, cpu_quota_per_sec, runtime_max, remain_after_exit}, `properties` and `ran` in place of `sacct`; usage errors exit 2. A `--run` interrupted while waiting (SIGINT, SIGTERM, SIGHUP) leaves the unit running, keeps its temporary `LAKE_CACHE_DIR` while the unit may still run (removed once it is gone or finished), writes nothing, exits 128 + the signal number and prints the recovery command (the same command without `--run`) with a WARN that recovery skips the source-unchanged-during-the-run check. Before launching, compare every configuration cheaply: [Before receipt work](../comparator.md#before-receipt-work).
