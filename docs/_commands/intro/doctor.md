| Form | What it does | Key flags |
|---|---|---|
| `doctor` | one `ok`/`warn`/`n/a` line each: version; install kind and path (an editable install inside a git checkout adds its short HEAD, branch, and behind/ahead counts against `origin/<branch>`, from local refs unless `--fetch`); registry path and schema version, ending `[source: flag|env|user-default|cwd]` (`doctor --json` adds `"source"` to that check); `user-default`: what `~/.lean-pkg/registry` points at (`ok`) or `n/a` when it is not set up; events path, ending `[source: flag|registry-sibling|env|sibling]`; `registry-repo`: the git work tree holding the registry with its HEAD, branch, behind/ahead of `origin/<branch>` (or "no origin remote" when there is none) and uncommitted tracked files, naming the registry files among them (`warn` when behind, ahead, detached, or the registry files are uncommitted: do not write from there yet; `n/a` outside a work tree); `leases`: live count, leases lapsing within 2 h and expired-but-unswept ones by name, and leases whose fields cannot be parsed (`warn` when any is non-empty); `time`: naive (offset-less, legacy) lease `claimed_at` / history `ts` values, read as UTC (`warn` when any); index path and entry count, ending `[source: flag|env|registry-sibling|cwd]`; `host`: the `comparator host-check` verdict (`warn` when this host cannot produce comparator receipts); `lake`, `lean`, `elan`, `git`, `gh`, `reuse`, `bwrap`, `comparator`, `nanoda`, `go`, `cargo`, `jq` on PATH (an `n/a` tool line says what the tool is for and when it is needed, so a host that only reads the registry still has a clean doctor: `comparator`, `nanoda`, `bwrap`, `go`, `cargo` and `jq` only produce comparator receipts on this host, `go`, `cargo` and `jq` being what `lean-pkg receipt comparator` needs to build the legacy comparator tools; `reuse` is the release gate's REUSE lint only; `gh` serves `promote`, `audit` and `reservoir check`; a `lake` or `lean` that is not elan's proxy in `$ELAN_HOME/bin`, default `~/.elan/bin`, is a `warn`, since it ignores each project's `lean-toolchain`; without `bwrap`, the `tool comparator` line adds "run `lean-pkg comparator host-check` to see whether this host can produce receipts", see [which hosts can produce receipts](../comparator.md#which-hosts-can-produce-receipts)); `gh auth`: the github.com account from `gh auth status` (`warn` when gh is present but not logged in, since `promote` and `audit` need it; `n/a` without gh); Python version. A check that raises prints `warn <item>: internal error ...` and the others still run. Exit 1 when the registry is unreadable or its schema version is unsupported (a missing registry counts as unreadable), else 0 | `[--fetch]` |
