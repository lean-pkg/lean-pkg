| Form | What it does | Key flags |
|---|---|---|
| `doctor` | one `ok`/`warn`/`n/a` line each: version; install kind and path (an editable install inside a git checkout adds its short HEAD, branch, and behind/ahead counts against `origin/<branch>`, from local refs unless `--fetch`); registry path and schema version, ending `[source: flag|env|user-default|cwd]` (`doctor --json` adds `"source"` to that check); `user-default`: what `~/.lean-pkg/registry` points at (`ok`) or `n/a` when it is not set up; events path, ending `[source: flag|registry-sibling|env|sibling]`; `registry-repo`: the git work tree holding the registry with its HEAD, branch, behind/ahead of `origin/<branch>` (or "no origin remote" when there is none) and uncommitted tracked files, naming the registry files among them (`warn` when behind, ahead, detached, or the registry files are uncommitted: do not write from there yet; `n/a` outside a work tree); `leases`: live count, leases lapsing within 2 h and expired-but-unswept ones by name, and leases whose fields cannot be parsed (`warn` when any is non-empty); `time`: naive (offset-less, legacy) lease `claimed_at` / history `ts` values, read as UTC (`warn` when any); index path and entry count, ending `[source: flag|env|registry-sibling|cwd]`; `host`: the `comparator host-check` verdict (`warn` when this host cannot produce comparator receipts); `lake`, `lean`, `elan`, `git`, `gh`, `reuse`, `bwrap`, `comparator`, `nanoda`, `go`, `cargo`, `jq` on PATH (an `n/a` tool line says what the tool is for and when it is needed, so a host that only reads the registry still has a clean doctor: `comparator`, `nanoda`, `bwrap`, `go`, `cargo` and `jq` only produce comparator receipts on this host, `go`, `cargo` and `jq` being what `lean-pkg receipt comparator` needs to build the legacy comparator tools; `reuse` is the release gate's REUSE lint only; `gh` serves `promote`, `audit` and `reservoir check`; a `lake` or `lean` that is not elan's proxy in `$ELAN_HOME/bin`, default `~/.elan/bin`, is a `warn`, since it ignores each project's `lean-toolchain`; without `bwrap`, the `tool comparator` line adds "run `lean-pkg comparator host-check` to see whether this host can produce receipts", see [which hosts can produce receipts](../comparator.md#which-hosts-can-produce-receipts)); `gh auth`: the github.com account from `gh auth status` (`warn` when gh is present but not logged in, since `promote` and `audit` need it; `n/a` without gh); Python version. A check that raises prints `warn <item>: internal error ...` and the others still run. `stack`: the declared [LTS stacks](../stacks/README.md) and the current one (`n/a`). Exit 1 when the registry is unreadable or its schema version is unsupported (a missing registry counts as unreadable), else 0 | `[--fetch]` |
| `doctor NAME` | the checks above, and the `stack` line for package NAME: its committed `lean-toolchain`, the Mathlib commit of its `lake-manifest.json` (against the stack's commit, not only the tag name, since a tag can be moved) and the tool digests of its recorded comparator receipt (`gate.comparator`, against the stack's Linux x86_64 digests), compared with the stack its `coverage.yaml` declares (`stack: NAME`). `ok`: `on stack NAME (supported until DATE)`; `warn`: a difference, a stack past its window, a stack this lean-pkg does not declare, or a lean-pkg outside the stack's range; `n/a`: no `stack:` key. Never an exit 1 (proposal 0004: doctor and verify "never refuse"). `--json` adds `stack` {name, declared, matches, supported_until, window, toolchain, mathlib, comparator_tools, lean_pkg, mismatches[], warnings[]}, `null` without NAME or the key | `NAME` `[--fetch]` |
| `doctor --package NAME` | the checks above, and one `producer lower-tier` and one `producer comparator` line for package NAME's gate receipts: the lean-pkg that wrote each (its `producer.lean_pkg`) against the running one, the check `status NAME` prints. `warn`: an older producer before a breaking upgrade-record entry that touches receipts, gate or claims (the line names the entries and `lean-pkg doctor --upgrade-from vPRODUCER --source DIR`), or a producer newer than the running lean-pkg; `ok`: the same version, or an older one with no such entry in between; `n/a`: no `producer` key (an older receipt) or no gate receipt recorded. Never an exit 1. `--json` adds `producer_skew` (the object `status --json` carries; `null` when NAME is not in the registry). Not with `--upgrade-from` (exit 2). See [Which lean-pkg wrote a receipt](../receipts.md#which-lean-pkg-wrote-a-receipt-producer-skew) | `--package NAME` `[--fetch]` |
| `doctor --upgrade-from OLD` | instead of the checks above, the **upgrade preflight**: what changed for a package author between two lean-pkg versions or commits (even when the version string is unchanged), read from a lean-pkg git checkout's objects and never by running the old code. Mechanical: `requires-python`, dependencies, executables, format markers (every `x/N` constant, the registry version, the formalization.yaml version), the on-disk key lists (registry package and lease, lower-tier and comparator receipts, formalization.yaml's derived keys), command paths and options from the help goldens (a renamed command or flag whose old spelling is an alias is `renamed`, not removed), the `--json` key sets, the alias tables and the packaged data files. Curated: the entries of `docs/upgrades/<version>.yaml` whose pull request lies in OLD..NEW (`behavior[]`, `breaking[]`), and the range's pull requests no record names (`uncurated[]`). OLD and NEW are a version (`0.10.0`: tag `v0.10.0`, else the `release: 0.10.0` commit) or any revision; `--json` schema `lean-pkg-upgrade/1`; read-only, no registry, no network; see [the design](../design/upgrade-preflight.md) and [the 0.11.0 notes](../upgrades/0.11.0.md) | `--upgrade-from OLD` `[--to NEW]` `[--source DIR]` |
