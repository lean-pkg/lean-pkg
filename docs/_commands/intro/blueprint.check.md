| Form | What it does | Key flags |
|---|---|---|
| `blueprint check NAME` | read-only: the blueprint cross-check. It runs [checkdecls](https://github.com/PatrickMassot/checkdecls) (Patrick Massot, Apache-2.0), never a parser of its own: on a clean checkout, `lake build`, then `lake exe checkdecls blueprint/lean_decls` (the list leanblueprint writes from the `\lean{...}` tags); every `NAME is missing.` line is reported. Then claims.yaml at HEAD: a claim whose `decl` the blueprint names must be a declaration checkdecls accepts (else a problem); claims outside the blueprint and blueprint names no claim carries are notes. checkdecls must be a dependency in `lake-manifest.json` at HEAD; without it the command prints the `require` line to add (lean-pkg never edits the lakefile). A package with no `blueprint/` directory and no declaration list is skipped (exit 0). Uncommitted changes to tracked files refuse. Exit 0 nothing missing, 1 a missing name, a claim problem or a refusal; `--json`: `commit`, `skipped`, `reason`, `decls_file`, `declarations`, `missing[]`, `checkdecls {rev, url, pinned}`, `claims {file, present, checked, problems[], outside_blueprint[], blueprint_without_claim[]}`. See [page: blueprint cross-check](../page.md#blueprint-cross-check) | `[--decls PATH]` |
