| Form | What it does | Key flags |
|---|---|---|
| `claims check [NAME]` | re-validate cached claims (schema, unique ids, acyclic supersession, declarations at the synced commit); exit 0 or 1. `--file PATH` instead schema-checks a working-copy claims file (schema only: there is no checkout, so declarations are not looked up; validate `claims.yaml` before the commit you will gate): no registry is read, `NAME` is optional and, if given, must be the file's `package`; `PASS`/`FAIL` first, exit 0 or 1, `--json` `{ok, path, claims, errors[]}`. With `NAME`, coverage `none` (no cached claims, no `claims.yaml` at HEAD) or `unsynced` (`claims.yaml` committed, nothing cached) is a failure (exit 1): no coverage is not ok. `--json` adds `coverage`, `cached_claims`, `claims_yaml` (`present`, `absent`, `unknown`), `legacy_claims[]` and `hint` per package. Without `NAME`, packages with no claims are skipped as before. A `NAME` that is an existing `.yaml`, `.yml` or `.json` file is a usage error naming `--file` (exit 2) | `[--file PATH]` |
