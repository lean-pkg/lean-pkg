| Form | What it does | Key flags |
|---|---|---|
| `register NAME` | the only write path for new packages; validated, deduping by name and by resolved checkout (`~/` expanded, relative paths taken from `$HOME`, stored `$HOME`-relative), auto-detects toolchain and Mathlib pin; a Lean root namespace (each `lean_lib` in `lakefile.lean` or `lakefile.toml`, else the top-level `*.lean` files) that another registered package's checkout also uses is a stderr note and a `notes` entry in `--json`, never a refusal; an empty `--path`, `--repo` or `--owner-project`, or a path resolving to `$HOME`, is refused; a `--path` that does not exist on this host is only a warning (`warn: local_path does not exist on this host`), and `lean_toolchain` and `mathlib_pin` are then recorded as null: fix the path later with `update NAME --path DIR --reason R`, then `update NAME --redetect`. NAME is the package name every later command takes. `--like OTHER` registers a sibling of a registered package (for example `lean-r2/` beside `lean/` in one manuscript repository; see [Sibling packages](../receipts.md#sibling-packages-in-one-repository)): `repo`, `owner_project`, `upstream_target` and `automation` are taken from OTHER unless given (visibility is never copied: it defaults to `private`); copying OTHER's `repo` is refused when both checkouts are on this host in different git repositories and `--repo` is absent (nothing written); a stderr note says whether the detected toolchain and Mathlib pin match OTHER's, never a refusal; `--json` gains `like` {name, copied[], toolchain {this, like, match}, mathlib_pin {this, like, match}} and the `registered` event `like`; an unknown OTHER is refused (exit 1); with neither `--repo` nor `--like` it is a usage error (exit 2). Warnings (`warn:` lines, `warnings[]` in JSON), never refusals: the checkout lies inside, or contains, another registered package's directory (every commit to the inner one is drift for the outer one's receipt); its `lake-manifest.json` has a path dependency outside the package directory (`gate` refuses that receipt) | `--repo URL` (or `--like OTHER`) `--path HOME-RELATIVE` `[--like OTHER]` `[--owner-project]` `[--visibility]` `[--status scratch|active|gate-pending|public]` (`public` needs `--visibility public` and `[--reason]`) `[--upstream-target none|mathlib|palomar]` `[--automation]` `[--notes]` `[--dry-run]` |
