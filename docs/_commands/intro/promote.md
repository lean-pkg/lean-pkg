| `promote NAME` | promotion checklist; dry run unless `--yes`; the flip is one-way. The checklist requires the claims ledger at the promote stage to be `ready` (every `reusable` claim verified, theorems and lemmas by the comparator tier too; a package without claims is `unknown` and refused; the line is `claims ledger ready: N required claim(s) verified (sha256:…)` or `claims ledger STATUS: REASON; first: ID: CODE` naming `claims ledger NAME`; `--json` gains `claims_ledger` {package_status, counts, required, reasons, ledger_digest}; see [Lifecycle](../lifecycle.md#claims-ledger)), both receipts and every comparator log committed at HEAD unmodified, and HEAD contained in `origin/<branch>` (local refs; the dry run never fetches); under `--yes` a failed `gh` query is a failure. `--yes` first runs `git fetch --prune --tags origin` with the refspecs `+refs/heads/*:refs/remotes/origin/*` and `+refs/pull/*/head:refs/remotes/origin/pr/*` (GitHub's pull-request heads are published with the repository), 120 s timeout, so the scan covers every branch, tag and pull-request head the remote holds; the first checklist line is then "fetched origin's branches, tags and pull-request heads: the scan covers them" or the `✗` "git fetch origin failed (...): cannot verify what the public flip would publish", which refuses. It also runs `public-safety NAME` (the whole repository when the package is a subdirectory of it: the line then reads "public-safety (whole repository: the package is a subdirectory): ...") and refuses while blocking hits remain, with the checklist line "public-safety: N hit(s) — fix the tree, or publish a fresh-history tree with `release --fresh-repo`; see `lean-pkg public-safety NAME`" (" (+W warning(s))" after the count when there are warn hits too); warn-only hits give the `WARN` line "public-safety: 0 blocking hit(s), N warning(s) (FAMILIES) — review with `lean-pkg public-safety NAME`" and do not block; `--skip-public-safety` replaces the scan with a `WARN` line. `--json` gains `public_safety` {skipped, hits, tree_hits, history_hits, block_hits, warn_hits, scope (`package` or `repository`), unscanned, unscanned_blocking}. Evidence that exists on disk but that git ignores (the gate and comparator receipts, the comparator logs, and the `comparator-stages/` files, `stages.json` and stage logs, beside them; judged by `git check-ignore -v`, so a force-added tracked file is never reported) is the `WARN` line "evidence on disk is git-ignored, so `git add` skips it: PATH (RULE), ...; un-ignore it: add `!.lean-receipts/` and `!**/.lean-receipts/**` to .gitignore after the ignoring rule (a `!PATH` line for evidence elsewhere), or `git add -f PATH`", RULE being `SOURCE:LINE:PATTERN` such as `.gitignore:3:*.log`; the `✗` for a required file that is not committed names the rule, "not committed: PATH (git-ignored by RULE)". `--json` gains `ignored_evidence[]` {path, rule} | `[--yes]` `[--skip-public-safety]` |
