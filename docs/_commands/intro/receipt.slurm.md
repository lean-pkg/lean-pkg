| Form | What it does | Key flags |
|---|---|---|
| `receipt slurm` | a lower-tier receipt from a finished Slurm job, in exactly the shape `gate --receipt` validates; reads and writes no registry. Checks, all before anything is written (every failure listed, any one refuses: exit 1, nothing written): the main job line of `sacct -j J --format=JobID,State,ExitCode,Elapsed,TotalCPU -P -n` (or `--sacct-file`, that output saved on a host with Slurm; three columns suffice; other columns need sacct's header line, which locates JobID, State and ExitCode by name, else `unexpected sacct format`) says `COMPLETED` and `0:0`; with `--stdout` (the job's `.out`) its one `verify-log-sha256` line equals the SHA-256 of the raw `--log`, and its `pre-manifest-sha256` and `post-manifest-sha256` lines are equal and equal the SHA-256 of `lake-manifest.json` committed at the commit (lines `KEY VALUE` or `KEY: VALUE`); without `--stdout`, the fallback: the log holds exactly one `verify-log-sha256: <hex>` line equal to the SHA-256 of the log without that line; `--stderr` (the `.err`), when given, is empty; `lean_toolchain` is `lean-toolchain` at the commit and `mathlib_rev` the manifest's `mathlib` rev there (else the log's `mathlib-rev:`), a disagreeing log line refuses; `sorry_count` is the log's `sorry-count:` line (never fewer than the log's `declaration uses 'sorry'` lines, else refused), else its `declaration uses 'sorry'` lines, counted only when the log shows the build finished (`Build completed successfully` or `lake build: ok`; neither a count nor a completion line refuses), and must be 0; `axioms` the log's `axioms:` line, else the union of its `#print axioms` output (neither refuses); `checker` is `--checker`, else the log's `checker:` line; optional `commit:`, `job-id:`, `generated-at:` lines must agree; a log with no `commit:` line is refused in the fallback mode (no `--stdout`), and with `--stdout` prints the stderr `WARN the verify log has no commit: line; it is bound to the commit only through lake-manifest.json` (JSON `log_commit_bound: false`; `true` with a matching line; the written receipt carries the same `log_commit_bound`, an additive key `gate` never reads, and when it is `false` the README entry gets a `- WARN:` line saying so); every field but `checker` is read from the RAW log, and a redaction that removes or alters a line the parser reads (Lean's sorry warnings, `#print axioms` output, a build-completion line, any `key:` line but `checker:`) refuses; after redacting the `/tmp/<account>-job` prefix, `/scratch/<user>/` and every `--redact` match, the public-safety scanner finds no blocking hit in the redacted log, the receipt JSON or the README entry (families listed, never the strings; besides the shared families it blocks this machine's user name and host name, full and short, at a word boundary, and a `/home/<x>` or `/Users/<x>` home directory with or without a trailing slash); a committed symlink at the commit that resolves into `.lean-receipts/` refuses (gate refuses it too); with `--append-readme`, a `README.md` that is not UTF-8 text, or a symlink, refuses before anything is written, and so does a symlinked `.lean-receipts/`. `job_id` is `slurm-<J>` (`--job` takes `J` or `slurm-J`). Writes `<c12>-slurm-<J>-verify.redacted.log` and `<c12>-slurm-<J>.json` (default `<repo>/.lean-receipts/`; `report_sha256` is the redacted log's SHA-256; a differing file already there is refused, except that a re-run differing only in a clock-stamped `generated_at` (no `generated-at:` line in the log) keeps the stored one), with `--stdout` the receipt also carries `job_stdout_sha256` and `manifest_sha256` (additive keys `gate` ignores), prints the README entry (state, exit, elapsed, TotalCPU, log name and hashes; with `--stdout` a `- Seal:` line with the job stdout and manifest SHA-256) and `next: lean-pkg gate NAME --check --receipt PATH`; `--append-readme` appends the entry to `README.md` beside the receipt (once; `--readme-heading`, `--readme-line`, `--tar-sha256` fill it; the entry's heading starts with the commit, so a `--readme-heading` that repeats this commit's SHA has it dropped). `--compress-log` writes the log as deterministic gzip `<c12>-slurm-<J>-verify.redacted.log.gz` instead (level 9, mtime 0, no file name): `report_sha256` stays the uncompressed log's SHA-256, the receipt gains the additive `report_compressed` {format: gzip, sha256 of the .gz, bytes uncompressed}, `sealed[]` lists the `.gz` (role `redacted-log.gz`, `receipt_key` `report_compressed.sha256`, `uncompressed_sha256`), restore with `gzip -dc X.log.gz > X.log` ([details](../receipts.md#a-compressed-sealed-log---compress-log)); without it a redacted log over 90 MiB prints a stderr WARN naming the flag. `--json` `{ok, receipt, log, report_sha256, raw_log_sha256, job_id, seal, log_commit_bound, report_compressed, sealed[], sacct, redactions, lines_redacted, checks[], readme_block, readme_appended, next, refusals[]}`; `sealed[]` {role, path, sha256, receipt_key} names every file the run wrote and bound (`receipt`, `redacted-log` with `report_sha256`, and for `receipt systemd` the normalised `unit.properties` with `unit_properties_sha256`), empty on a refusal: take a sidecar from it, never by its file name (`properties` in `receipt systemd`'s JSON is the raw, unsealed capture); usage errors (a missing `--log`/`--stdout`/`--stderr` file, a bad `--redact` regex) exit 2. `--template` (no other flag, no registry) prints a minimal sbatch wrapper whose `.out`, empty `.err` and log carry every line the receipt reads (the three seal lines; `checker:`, `sorry-count:`, `axioms:`, `lean-toolchain:`, `commit:`, `job-id:`, `generated-at:`), with placeholders for the package's own commands, a node-local work directory and `LEAN_NUM_THREADS` 3, and an exact-runtime preflight before any tool runs: the C locale (`LC_ALL=C LANG=C PYTHONUTF8=1`, an `#SBATCH --export` line and an `export`; stderr stays strict) and a `type -P` probe of every executable it needs, which fails the job before the work ([details](../receipts.md#a-lower-tier-receipt-from-a-slurm-job)). `--check` preflights a job's files (a short trial job before the long one): the seal, stderr, log-line, field and public-safety checks, every problem named, sacct not run (checked only from `--sacct-file` with `--job`), commit-side checks only with `--commit`; writes nothing; exit 0/1; `--json` `{ok, check, written: [], raw_log_sha256, log_commit_bound, checks[], problems[]}` (`log_commit_bound` as in a producing run, `null` without `--commit`). `--artifacts DIR` (needs `--stdout`; also with `--check`) checks the job's artifact seal (the template's optional `ARTIFACTS_DIR`): the SHA-256 of the manifest `DIR/artifacts.sha256` (`--artifacts-manifest NAME` for another name) must equal the stdout's one `artifacts-manifest-sha256` line, and every file under `DIR` is rehashed in 1 MiB chunks against it; a missing, extra or changed file, a symlink, a special file, a path-traversal, duplicate or unsorted entry refuses; the receipt gains the additive `artifacts_manifest_sha256` (`gate` ignores it), the manifest is written beside it as `<c12>-slurm-<J>-artifacts.sha256` (`sealed[]` role `artifacts.sha256`), `--json` gains `artifacts` {ok, dir, files, bytes, manifest, manifest_sha256}; without `--artifacts` nothing changes ([Recollecting a finished job](../receipts.md#recollecting-a-finished-job)). `--contracts-preflight [--repo DIR]` runs, before you submit the job, the contracts-only diagnostic on every comparator configuration of the checkout (its modules built there) and refuses (exit 1) when one differs, a configured module is not built or the diagnostic cannot run; writes nothing; `--json` `{ok, contracts_preflight, written: [], checks[], refusals[], report}` ([details](../receipts.md#contracts-preflight---contracts-preflight)). `--preflight-deps --deps-tar T` (or `--deps-dir D`, a directory holding `.lake/packages`) `[--commit SHA] [--entries GLOB]...` checks, before submitting, that the staged dependency cache holds what the verifier's own entry files need: the `import` closure of the entry files committed at `--commit` (default `HEAD`; default entries `Verify/**/*.lean`, `Audit/**/*.lean`, `OwnedAudit/**/*.lean`, `**/AxiomCheck*.lean`, `**/TypeCheck*.lean`, `**/Examples*.lean`, `**/OwnedAudit*.lean`; `--entries` replaces them) is followed through the package's committed modules and the dependencies' sources in the cache, and every external module in it needs its `.olean` and `.ilean` as regular files in exactly one manifest package (`import Mathlib` needs every module `Mathlib.lean` imports, transitively); every git package of `lake-manifest.json` must be in the cache at the manifest's `rev` (`.git/HEAD`, resolved through `refs/` or `packed-refs`); a missing module, a module no package provides (toolchain roots `Init`, `Std`, `Lean`, `Lake` aside), a module whose source is not in the cache, a missing package, a stripped or other-rev checkout, a `path` package, no entry file, or an unreadable tarball (gzip, bzip2, xz, plain) is a problem; reads only (the tarball in one pass, never extracted), builds and writes nothing; exit 0/1; `--json` `{ok, preflight_deps, commit, entries[], required_external_modules, missing_count, missing[] {module, package, files, required_by} (first 500), checks[], problems[]}`. It adds a check before submission; every check inside the job is unchanged. Before launching, compare every configuration cheaply: [Before receipt work](../comparator.md#before-receipt-work).
