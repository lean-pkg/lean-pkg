| Form | What it does | Key flags |
|---|---|---|
| `new NAME` | scaffold a minimal Lean 4 package in `./NAME` (or `--dir DIR`; refused when it exists and is not empty) and `git init` it, for the [quickstart](../quickstart.md): the [getting-started template](../getting-started.md#start-from-scratch) (`lean-toolchain`, `.gitignore`, `lakefile.toml`, `MOD.lean`, `MOD/Challenge.lean`, `MOD/Solution.lean`, `comparator.json`) plus `MOD/Axioms.lean` (`#print axioms`), `claims.yaml` (one reusable claim), `coverage.yaml` (below), `CITATION.cff` (the author is `--author`, else `git config user.name`; a name with no space prints a warning, since it looks like a handle), `LICENSE` with the same text in `LICENSES/<SPDX>.txt`, a `REUSE.toml` that puts every file, receipts and logs included, under that license (so `reuse lint`, which [`publish --dry-run`](publish.md) runs, passes), a `README.md` carrying the lean-pkg credit, `verify.sh`, the lower-tier check whose log [`receipt systemd --run`](receipt-systemd.md) reads, and `lean-pkg-binding.yaml` (`docs_descendants: true`, with a comment saying what it permits), the committed [docs-only opt-in](../receipts.md#docs-only-descendants-opt-in): committed with the package, it keeps the receipts bound when the README page is committed after the verified commit; `--evidence-only` leaves it out (`--json` `binding_file`: the file, or null). The `lakefile.toml` names its library in `defaultTargets`, so a bare `lake build` builds it, and globs both `MOD` and `MOD.+`, so the root module `MOD.lean` (written empty, for the library's imports) is built and a Solution may import the library through it. Nothing is committed, fetched or built, and no registry is read or written. `--stack NAME` pins a declared [LTS stack](../stacks/README.md): its `lean-toolchain` and Mathlib tag, and `stack: NAME` in `coverage.yaml`, which [`doctor NAME`](doctor.md), [`verify`](verify.md) and `page` check against the committed pins; `--stack current` is the newest declared stack whose window covers today and `--stack none` the newest pins with no key. Without `--stack`, `--kind paper` takes the current stack (the newest pins, with a warning, when none is current) and `--kind library` the newest pins (libraries aimed at Mathlib follow its newest release; proposal 0004, open question 7): the newest stable Lean release lean-pkg ships in its table, with the matching Mathlib tag, and a release candidate only when no stable release is newer. The output names the pins, and says when they are a release candidate (`--json`: `release_candidate`). `new` reads no network. An undeclared stack exits 2, listing the declared ones. The stack's comparator tools are the ones its toolchain bundles, so the toolchain pin is theirs. `--kind paper` (the default) writes a `kind: paper` `coverage.yaml` that is incomplete on purpose: `manuscript.version: unposted` and `FILL-ME` markers, which [`coverage check`](coverage.md) and `page` refuse until you name the paper and its results; [`formalization anchor --write`](formalization.md) then binds the posted version (no manuscript is invented). `--kind library`: one main result naming the example claim, which `coverage check` accepts as written. `--no-mathlib`: core Lean only (`lean-pkg receipt comparator` then needs `COMPARATOR_RECEIPT_NO_MATHLIB=1`; `verify.sh` logs `mathlib-rev: none`, the receipt's explicit value for a package without Mathlib). The name: lower-case letters, digits and single hyphens, starting with a letter; a library named like Lean's or a Mathlib dependency's root namespace is refused (exit 2) | `[--kind paper\|library] [--stack NAME\|current\|none] [--dir DIR] [--module MOD] [--no-mathlib] [--author TEXT] [--license Apache-2.0\|MIT] [--evidence-only] [--json]` |
