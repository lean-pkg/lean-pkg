else `info`); every finding has a `level` (`warn` or `info`); informational findings (never fixed): `receipt-untracked` (a recorded gate or comparator receipt exists in the working tree but is not tracked at the reference branch tip) and `duplicate-path` (two packages whose `local_path` resolve to the same checkout) and `duplicate-namespace` (two checkouts declaring the same Lean root namespace, which cannot be built or imported together; `info` under `--promotion` too); `palomar-not-ready` (`warn`; only for packages aiming at Palomar: `upstream_target: palomar` or a recorded `palomar` entry, and status not `scratch`, `archived` or `upstreamed`): the `error` gaps `palomar check NAME` finds at the commit it reads (gate-bound, else HEAD), with their count, codes and the command `lean-pkg palomar check NAME`; the last line is unchanged for scripts); `--quiet` prints only that line (or `no findings`), `--json` unchanged; `--json` adds `counts` `{warn, info}`; a failed gh query is the check `gh-missing`/`gh-not-authenticated`/`gh-no-access`/`gh-not-found`/`gh-error` (`--no-gh`: `gh-skipped`) | `[--fix]` `[--toolchain-floor VERSION]` `[--promotion]` `[--no-gh]` `[--quiet]` |
