# Upgrading to 0.13.0 (from 0.12.0)

The changes merged after 0.12.0 that a package author should know about.
The machine-readable record is [0.13.0.yaml](0.13.0.yaml). This page is
filled in as pull requests merge, until 0.13.0 is cut. `lean-pkg doctor
--upgrade-from 0.12.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.

The large-artifact change asks for a step only from a package that committed
the packing script; recording a container image and preflighting run tools are
optional:

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `receipt-container-image` | #245 | Receipts record the container image a job ran in as the additive key `container` (the SIF's SHA-256 or the OCI digest); `receipt check` and the page show it. A receipt without it is unchanged. | Optional: regenerate `verify.sbatch` with `lean-pkg receipt slurm --template` to record the image. |
| `systemd-require-tools-remain-after-exit` | #250 | `receipt systemd --run --require-tools A,B,...` resolves each named executable like `type -P` in the unit's `PATH` before the unit is created, and refuses with nothing started if one is missing; resolved paths and SHA-256 go to stderr and `--json` `run_tools`, never into the receipt. The exported unit property set gains `RemainAfterExit` (recorded, never required) and is documented exactly in [receipts](../receipts.md); `MainPID` is not exported. | Optional: commit a per-version run-tools list and pass it with `--require-tools`; a wrapper reading `unit.properties` should require only the documented required properties. |
| `extract-disabled-lean-warning` | #239 | `lean-pkg-extract plan` warns about `*.lean.<suffix>` files under a root that it excludes or refuses (disabled negative fixtures, which the import check does not read), pointing at [Disabled negative fixtures](../extract.md#disabled-negative-fixtures-after-a-namespace-or-import-transport) and `lean_diag`. `ok` and the exit code do not change. | Nothing is required; inspect the named files with `lean_diag`'s expected-reason check. |
| `dup-constants-path-subdir-deps` | #240 | `lean_pkg.dup_constants` finds `path` dependencies at their `dir` (e.g. `vendor/NAME`) and `git` dependencies with a `subDir`; 0.12.0 refused such projects before the audit ([duplicate constants](../duplicate-constants.md)). | Nothing; projects with path or subDir dependencies can now be audited. |
| `large-artifact-pack-guards` | #244 | `pack-artifacts.sh` in [docs/receipts.md](../receipts.md) refuses an output directory that is the raw tree or lies inside it (or the reverse), and two paths in the raw tree that are hardlinks of one file. Before, a nested output was packed into its own archive, and a hardlink packed but the collector refused the archive. | Replace a committed copy with the page's current script. Keep the output next to the raw tree; copy a raw tree with internal hardlinks without links before packing. |
| `toolchain-advisories` | #246 | `gate`, `gate --check`, `receipt check` and `palomar check` print one `WARN: toolchain advisory ...` line per entry of lean-pkg's [toolchain advisories](../receipts.md#checking-a-published-packages-receipts-receipt-check) list that names the receipt's toolchain (any release before v4.34.1, and v4.35.0-rc1 and -rc2), and `--json` gains `toolchain_advisories[]`. Never a refusal. `page --write` adds a *Toolchain advisory* line under *How this was checked*; `page --check` leaves such lines out of its comparison (an existing page stays current) and prints a non-failing `NOTE` per advisory the page does not show yet. | Nothing. |

PRs #238 and #242 (draft proposals), #248 (this record's follow-up for
#238), #247 (FAQ and trust-model docs), #249 (the first LTS stack,
`lts-2026.10`, as documentation under docs/stacks) and #PRSELF (this page's
row for #250) were read for this record; none needs anything from a package
author.
