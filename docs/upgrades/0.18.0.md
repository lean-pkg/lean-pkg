# Upgrading to 0.18.0 (from 0.17.0)

The changes merged after 0.17.0 that a package author should know about.
The machine-readable record is [0.18.0.yaml](0.18.0.yaml). This page is
filled in as pull requests merge, until 0.18.0 is cut. `lean-pkg doctor
--upgrade-from 0.17.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.

Nothing so far is required of a package author:

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `preflight-deps-fill-plan` | #275 | New flags `receipt slurm --preflight-deps --fill-plan DONOR [--plan-out FILE] [--base-list FILE]` (field report #5): steps 1-4 of the [donor-fill recipe](../receipts.md#filling-missing-dependency-artifacts-from-a-pinned-donor), read-only. It keeps every missing module of the base cache (the 500 cap of `missing[]` is for display only), checks the donor (`lean-toolchain` byte for byte, every manifest rev, no source edits by `git status`, the first 80 bytes of each candidate `.olean` equal to the base's), lists every file the donor holds under each module's path (all artifact families) with size and SHA-256, and refuses an addition that is a base member, under one, under the package's own `.lake/build` or in its root namespaces. Each refusal has its own code (`refusals[].code`), exit 1. With `--plan-out`, only when the plan is sound, it writes the additions list and `FILE.provenance.json` (collector provenance, never a job seal). It writes no archive and never touches the base, the donor or `.lake/build`. | Nothing for a package author. To fill missing modules from a cache built from the same pins: `--fill-plan DONOR --plan-out add.list`, write the new archive by hand (recipe steps 5-7), and rerun `--preflight-deps` on it before submitting. |
