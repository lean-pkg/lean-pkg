# Upgrading to 0.16.0 (from 0.15.0)

The changes merged after 0.15.0 that a package author should know about.
The machine-readable record is [0.16.0.yaml](0.16.0.yaml). This page is
filled in as pull requests merge, until 0.16.0 is cut. `lean-pkg doctor
--upgrade-from 0.15.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.

Nothing so far is required of a package author:

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `formalization-render-repo` | #271 | `formalization render NAME --repo DIR` (field request) renders `formalization.yaml` from another checkout for one call, read-only and never saved, with the checkout rules and stderr note of `page --repo`. Claims, comparator configurations, the kept keys and the receipts are read at DIR's committed HEAD, never its working tree; the registry's gate receipt feeds `status.sorry_count`, `axioms` and `evidence` only when it validates at that HEAD, else they are omitted with a warning. Refused with `--write` (exit 2) and on `anchor`. `--json` gains `repo_override` (`path`, `registered_path`, `remote_match`, `head`, `source`, `receipt_facts`), `null` without the flag. | Nothing for a package author. To preview a candidate checkout's metadata while the accepted one stays registered: `formalization render NAME --repo DIR --out FILE` ([docs](../formalization.md#modes)). |
