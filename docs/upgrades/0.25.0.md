# Upgrading to 0.25.0 (from 0.24.0)

The changes merged after 0.24.0 that a package author should know about.
The machine-readable record is [0.25.0.yaml](0.25.0.yaml). This page is
filled in as pull requests merge, until 0.25.0 is cut. `lean-pkg doctor
--upgrade-from 0.24.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.
The name 0.25.0 is provisional: the release is named by what it holds
(RELEASING.md, "When to tag"), and the record is renamed with it.

Nothing so far is required of a package author.

## Nothing required

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `seal-bundle` | #414 | New command [seal-bundle](../commands/seal-bundle.md): a seal job's bundle (job script from the package's template, module lists, reproducible `source.tgz`, `INPUT-SHA256SUMS`) derived from the receipts and the commit; `--check DIR` compares an existing one. | Nothing. To stop hand-editing seal bundles: write a `seal-bundle/1` spec, `--check` the last hand-made bundle, then render the next. |
| `doctor-new-machine` | #416 | `doctor` with no registry configured anywhere says `n/a registry: none yet` and how to make one, and exits 0 ([doctor](../commands/doctor.md)); a named registry that is missing still fails. | Nothing. A script that read exit 1 as "no registry" reads the registry line. |
| `claims-summary-length-warning` | #412 | `claims check` warns, never fails, on a claim or manuscript-finding `summary` of 281 to 300 characters, so a later small edit does not meet the 300-character refusal unannounced (`--json` `warnings[]`; [claims check](../commands/claims-check.md)). The refusal is unchanged. | Nothing. Shorten a warned summary when convenient. |
