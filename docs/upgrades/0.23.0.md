# Upgrading to 0.23.0 (from 0.22.0)

The changes merged after 0.22.0 that a package author should know about.
The machine-readable record is [0.23.0.yaml](0.23.0.yaml). This page is
filled in as pull requests merge, until 0.23.0 is cut. `lean-pkg doctor
--upgrade-from 0.22.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.
The name 0.23.0 is provisional: the release is named by what it holds
(RELEASING.md, "When to tag"), and the record is renamed with it.

Nothing so far is required of a package author.

## Nothing required

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `gate-check-palomar-advisory-intent` | #PRNUM | `gate --check` prints its Palomar advisory (`WARN: palomar: not submittable ...`) only for a package that aims at Palomar: `upstream_target: palomar` or a recorded Palomar entry, and a status other than scratch, archived or upstreamed, the predicate `registry audit` uses ([#387](https://github.com/lean-pkg/lean-pkg/issues/387)). Any other package gets no WARN. JSON `palomar_check` gains `skipped`: null for a package aiming at Palomar, `"not aiming at Palomar"` for any other, whose readiness fields are still filled. `publish --dry-run` and `palomar check` are unchanged ([gate](../commands/gate.md)). | Nothing. To keep the advisory for a package headed to Palomar, run `lean-pkg update NAME --upstream-target palomar`; a script reading `gate --check --json` `palomar_check` sees one more key. |

PR #384 (documentation: proposals 0002, 0003, 0008 and 0009 marked
implemented in 0.22.0; no code changes) was read for this record; it changes
nothing for a package author.
