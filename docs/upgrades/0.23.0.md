# Upgrading to 0.23.0 (from 0.22.0)

The changes merged after 0.22.0 that a package author should know about.
The machine-readable record is [0.23.0.yaml](0.23.0.yaml). This page is
filled in as pull requests merge, until 0.23.0 is cut. `lean-pkg doctor
--upgrade-from 0.22.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.
The name 0.23.0 is provisional: the release is named by what it holds
(RELEASING.md, "When to tag"), and the record is renamed with it.

Nothing so far is required of a package author.

## Nothing required

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `gate-check-next-command` | #389 | `gate NAME --check --agent A` runs the check with one stderr note (`--check` takes no lease; `--agent A` is for the writing gate) instead of a usage error, exit 2; `--check --refresh-formalization` is still refused. A passing check, on a status the writing gate takes, ends with `next: lean-pkg gate NAME --receipt R ... --agent A`, the evidence flags it was given and `--agent A` (else the placeholder `AGENT`); `--json` gains `next_command` (`null` when the check fails or the status needs another step first). After `--check --repo DIR` away from the registered `local_path` a line adds that the writing gate binds the registered checkout ([#386](https://github.com/lean-pkg/lean-pkg/issues/386), [gate](../commands/gate.md)). | Nothing. Run the printed `next:` command to record the gate, in the registered checkout. |

PR #384 (documentation: proposals 0002, 0003, 0008 and 0009 marked
implemented in 0.22.0; no code changes) was read for this record; it changes
nothing for a package author.
