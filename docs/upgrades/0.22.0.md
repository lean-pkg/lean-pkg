# Upgrading to 0.22.0 (from 0.21.0)

The changes merged after 0.21.0 that a package author should know about.
The machine-readable record is [0.22.0.yaml](0.22.0.yaml). This page is
filled in as pull requests merge, until 0.22.0 is cut. `lean-pkg doctor
--upgrade-from 0.21.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.
The name 0.22.0 is provisional: the release is named by what it holds
(RELEASING.md, "When to tag"), and the record is renamed with it.

## Act before you run repo export

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `repo-export-explicit-identity` | #344 | `repo export` sets the author and committer of the export commit explicitly (#339): `--author 'NAME <EMAIL>'`, else `user.name` and `user.email` of the source repository's local git config; the global identity, which put a personal address into public history, is never used. With neither the export refuses ("no identity for the export commit: pass --author ...", exit 1, nothing written), and an address that is not a GitHub noreply one (`ID+LOGIN@users.noreply.github.com` or `LOGIN@users.noreply.github.com`) refuses unless `--allow-author-email` is given; `--dry-run` refuses the same way. The export's own public-safety scan checks that identity and the commit message, so a private pattern in either refuses whatever the flags ([repo export](../commands/repo-export.md)). | Set a noreply identity in the source repository (`git -C SRC config user.name NAME`, `git -C SRC config user.email ID+LOGIN@users.noreply.github.com`) or pass `--author 'NAME <ID+LOGIN@users.noreply.github.com>'`. To publish another address on purpose, add `--allow-author-email`. |

## Migrate off the registry opt-in before it is removed

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `registry-docs-descendants-deprecated` | #360 | The registry route of the docs-only opt-in is deprecated (#319, proposal 0002): the record's `docs_descendants: true` with no `lean-pkg-binding.yaml` at the receipts' commit, and `update NAME --accept-docs-descendants`, which sets it. It keeps working, with a stderr `WARN: deprecated: ...` line and `--json` `deprecations[]`, in `gate`, `gate --check` and `comparator` when the docs-only rule admitted HEAD through the record, in `publish` whenever the opt-in exists only in the record, in `update --accept-docs-descendants` and in `page --write`. It is removed no earlier than the latest of 1.0.0, one minor release after this one, and two minor releases plus 60 days; the veto (`docs_descendants: false`) stays ([docs-only descendants](../receipts.md#docs-only-descendants-opt-in)). | `lean-pkg update NAME --write-binding-file`, commit `lean-pkg-binding.yaml` in a commit of its own, then run the verify step again so the new receipts bind a commit that contains it. |
| `page-write-binding-file` | #360 | `page --write` on a gated package without `lean-pkg-binding.yaml` at its gated commit keeps the registry route as before, now with the deprecation `WARN`, and writes the file into the working tree, never staged and never over an existing path (`--json` `binding_file`); with the file at that commit it does nothing about the opt-in ([the docs-only opt-in](../page.md#the-docs-only-opt-in)). | Commit README.md without the new file (`git add README.md`, not `git add -A`), and the file on its own right before the next verify run. |
