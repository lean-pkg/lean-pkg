# Upgrading to 0.22.0 (from 0.21.0)

The changes merged after 0.21.0 that a package author should know about.
The machine-readable record is [0.22.0.yaml](0.22.0.yaml). This page is
filled in as pull requests merge, until 0.22.0 is cut. `lean-pkg doctor
--upgrade-from 0.21.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.
The name 0.22.0 is provisional: the release is named by what it holds
(RELEASING.md, "When to tag"), and the record is renamed with it.

## Nothing required

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `commit-flags-on-write-commands` | #322 | `--commit`, `--push` and `--no-commit` appear in the help of the commands that can write the registry (and of `verify`, which passes them on) only. A read-only command (`list`, `next`, `status`, `public-safety`, `claims check`, ...) still accepts them after its name, and notes `--commit ignored: read-only command` on stderr, as before. | Nothing: every invocation parses and behaves as before; only `--help` texts change. |
| `repo-for-the-checkout` | #322 | The package checkout is `--repo DIR` on every command: `lean-pkg receipt comparator` (and the `comparator-receipt` program), `python3 -m lean_pkg.claim_axioms` and `python3 -m lean_pkg.dup_constants` said `--project`, which stays a permanent alias with a stderr note in text mode (`lean-pkg help aliases`). `lean-exercise --project` (a prebuilt Mathlib project) is unchanged. | Nothing. Scripts may keep `--project`; write `--repo` in new ones. |

## Nothing required

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `lower-receipt-schema-marker` | #324 | `receipt slurm` and `receipt systemd` (alias `receipt local`) write `"schema": "lower-receipt/1"` as the first key of every lower-tier receipt. A receipt without it (every receipt written before) is version 0 and is judged exactly as before, forever. A newer `lower-receipt/N` is refused, naming the upgrade, and any other `schema` value is refused ([on-disk formats](../formats.md)). | Nothing. Committed receipts keep validating and are never rewritten; a script comparing a receipt's exact key list sees one more key, first. |
| `event-line-version` | #324 | Every new line of `lean-package-events.jsonl` carries `v: 1`; a line without `v` is version 0 and is read as before. The prior-art note of `lease claim` skips a line with a newer or unreadable `v` and warns. Every event name and its keys are documented ([on-disk formats](../formats.md#event-log)). | Nothing. A tool reading the event log can treat a line without `v` as version 0. |
| `new-root-module-glob` | #0 | `lean-pkg new` writes `globs = ["MOD", "MOD.+"]`, as published packages do, and an empty root module `MOD.lean`; with `MOD.+` alone Lake never built `MOD.lean`, so a Solution importing the library through it failed (#326). | Nothing for a new scaffold. An older scaffold whose Solution imports `MOD.lean` adds `"MOD"` to its `globs`. |
| `new-stable-pins` | #0 | Without `--stack`, `lean-pkg new` pins the newest stable Lean release it ships (now `v4.35.0`, with Mathlib `v4.35.0`; it was `v4.35.0-rc2`), and a release candidate only when no stable release is newer, which the output then says; `--json` adds `release_candidate` (#327). | Nothing. An `rc2` scaffold may move to `v4.35.0`. |

row, #310 to #320, and proposals 0002 and 0003 marked accepted; no code
changes) was read for this record; it changes nothing for a package author.

that at the end of every run, CI jobs have time limits, a pip cache,

`make public-safety`, `make test` and the `tomllib` import lose their
loose ends; #310 to #313) was read for this record; it changes nothing for
a package author.

PR #331 (documentation: proposal 0008, a compute receipt from a CI runner,
GitHub Actions first, as a draft for the maintainer's decision; no code
changes) was read for this record; it changes nothing for a package author.
