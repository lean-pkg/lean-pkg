# Upgrading to 0.22.0 (from 0.21.0)

The changes merged after 0.21.0 that a package author should know about.
The machine-readable record is [0.22.0.yaml](0.22.0.yaml). This page is
filled in as pull requests merge, until 0.22.0 is cut. `lean-pkg doctor
--upgrade-from 0.21.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.
The name 0.22.0 is provisional: the release is named by what it holds
(RELEASING.md, "When to tag"), and the record is renamed with it.

## Nothing required

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `commit-flags-on-write-commands` | #322 | `--commit`, `--push` and `--no-commit` appear in the help of the commands that can write the registry (and of `verify`, which passes them on) only. A read-only command (`list`, `next`, `status`, `public-safety`, `claims check`, ...) still accepts them after its name, and notes `--commit ignored: read-only command` on stderr, as before. | Nothing: every invocation parses and behaves as before; only `--help` texts change. |
| `repo-for-the-checkout` | #322 | The package checkout is `--repo DIR` on every command: `lean-pkg receipt comparator` (and the `comparator-receipt` program), `python3 -m lean_pkg.claim_axioms` and `python3 -m lean_pkg.dup_constants` said `--project`, which stays a permanent alias with a stderr note in text mode (`lean-pkg help aliases`). `lean-exercise --project` (a prebuilt Mathlib project) is unchanged. | Nothing. Scripts may keep `--project`; write `--repo` in new ones. |

## Nothing required

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `lower-receipt-schema-marker` | #324 | `receipt slurm` and `receipt systemd` (alias `receipt local`) write `"schema": "lower-receipt/1"` as the first key of every lower-tier receipt. A receipt without it (every receipt written before) is version 0 and is judged exactly as before, forever. A newer `lower-receipt/N` is refused, naming the upgrade, and any other `schema` value is refused ([on-disk formats](../formats.md)). | Nothing. Committed receipts keep validating and are never rewritten; a script comparing a receipt's exact key list sees one more key, first. |
| `event-line-version` | #324 | Every new line of `lean-package-events.jsonl` carries `v: 1`; a line without `v` is version 0 and is read as before. The prior-art note of `lease claim` skips a line with a newer or unreadable `v` and warns. Every event name and its keys are documented ([on-disk formats](../formats.md#event-log)). | Nothing. A tool reading the event log can treat a line without `v` as version 0. |
| `new-root-module-glob` | #334 | `lean-pkg new` writes `globs = ["MOD", "MOD.+"]`, as published packages do, and an empty root module `MOD.lean`; with `MOD.+` alone Lake never built `MOD.lean`, so a Solution importing the library through it failed (#326). | Nothing for a new scaffold. An older scaffold whose Solution imports `MOD.lean` adds `"MOD"` to its `globs`. |
| `new-stable-pins` | #334 | Without `--stack`, `lean-pkg new` pins the newest stable Lean release it ships (now `v4.35.0`, with Mathlib `v4.35.0`; it was `v4.35.0-rc2`), and a release candidate only when no stable release is newer, which the output then says; `--json` adds `release_candidate` (#327). | Nothing. An `rc2` scaffold may move to `v4.35.0`. |
| `coverage-check-offline` | #335 | `lean-pkg coverage check --file coverage.yaml [--claims claims.yaml] [--comparator comparator.json ...]`, without `NAME`, checks `coverage.yaml` with no registry record and no receipt (#328): the schema and its length limits, the manuscript version, the claim ids against the claims file, reusable claims no row names (a warning), the comparator theorems against the rows; the checks that need the registry or a receipt are listed as skipped. With `NAME` the command is unchanged ([coverage check](../commands/coverage-check.md)). | Nothing required. Run it before the commit you will gate. |
| `verify-preflight` | #335 | `lean-pkg verify NAME` runs a preflight first (#325): the `claims/1` check on the claims file committed at `HEAD` and, when `coverage.yaml` is committed, the offline coverage check; a refusal stops verify before any receipt, nothing written. Placeholder text and an unposted manuscript are warnings there. `--json` `steps[]` begins with `0/3 preflight` ([verify](../commands/verify.md)). | Nothing for valid files. An invalid committed file now stops verify before the receipts: fix it in a new commit and run verify again. |
| `report-redaction-of-attached-sections` | #336 | `report` no longer refuses every report when the registry has a live lease: the blocking guard scans the user's text and each attached section (not the report's own prose, where a derived name such as `home` matched) and a refusal names the section (`--json` `sections[]`, additive); a private name in the user's own text is still redacted, not refused. Attached sections show `<agent>`, `<workspace>`, `<contact>` for registry names, and the local paths doctor and the version line name become whole placeholders (`<lean-pkg-install>`, `<lean-pkg-checkout>`, `<python>`, `<registry-repo>`, `<index-dir>`, `<events-path>`) instead of a partly redacted path. | Nothing. A script matching `[…]` or `~/...` for one of these in a report body sees the placeholder. |
| `ci-receipt-github-actions-level-1` | #338 | Stage S1 of proposal 0008 (#318): a built-in-only scheduler and site profile `github-actions` (job id `gha-<run_id>-<run_attempt>`), and an additive `ci` block of `lower-receipt/1` naming the run ([the `ci` block](../formats.md#the-ci-block)). `gate`, `gate --check` and `receipt check` refuse a block that fails a level-1 rule, each named; a receipt whose block passes backs `compute: [{cluster: github-actions, jobs: [gha-R-A]}]`, and a `gha-` receipt without it gates and backs nothing. Level 1 never renders the GitHub Actions sentence; a README carrying it fails `page --check`. `page --json` gains `level`, `levels` and `sentence` per site under `sites`; the legacy top-level key stays `easley` only. Newly refused: a package profile named `github-actions`, one naming that scheduler, and `{runs}` outside a built-in level-2 profile ([compute sites](../sites.md#github-actions)). | Nothing for a package on Slurm or `receipt local`. A script reading `page --json` `sites` sees three more keys per site. |
