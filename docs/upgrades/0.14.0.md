# Upgrading to 0.14.0 (from 0.13.0)

The changes merged after 0.13.0 that a package author should know about.
The machine-readable record is [0.14.0.yaml](0.14.0.yaml). This page is
filled in as pull requests merge, until 0.14.0 is cut. `lean-pkg doctor
--upgrade-from 0.13.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.

Nothing so far is required of a package author. Three changes are optional: the blueprint check,
recording per-claim axioms (which, once adopted, needs fully qualified claim names), and mapping a
claim to its comparator theorem with `judged_as` (which needs a new gated commit):

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `blueprint-check-checkdecls` | #260 | New read-only `lean-pkg blueprint check NAME`: it runs [checkdecls](https://github.com/PatrickMassot/checkdecls) on the blueprint's `blueprint/lean_decls` after `lake build` at HEAD, reports the missing names, and checks that every claim whose `decl` the blueprint names is a declaration checkdecls accepts. A package without a blueprint is skipped. See [page: blueprint cross-check](../page.md#blueprint-cross-check). | Optional: add the pinned `require checkdecls` line from that section, run `lake update checkdecls`, commit the lakefile and `lake-manifest.json`, then run the command. |
| `receipt-claim-axioms` | #262 | Receipts record the axioms of **every** claim in `claims.yaml` as the additive key `claim_axioms`, read after the build by core Lean's `collectAxioms` on the built environment (`ClaimAxioms.lean`, run by `receipt slurm --template` and by the `verify.sh` of `lean-pkg new`), not only the `#print axioms` output of the printed theorems. A missing, sorried or unchecked claim refuses the receipt; `gate` refuses an axiom outside `gate.axioms_allowed`; `receipt check` and the page read it ([per-claim axioms](../receipts.md#per-claim-axioms-claim_axioms)). A receipt without the key is unchanged. | Before adopting it, make every `decl` in `claims.yaml` fully qualified (a bare or partial name refuses the receipt); `python3 -m lean_pkg.claim_axioms --project .` reports any that are not. Then, optionally, regenerate `verify.sbatch` with `lean-pkg receipt slurm --template` (or copy the claim-axioms block of a new `verify.sh`). |
| `claims-judged-as` | #261 | `claims.yaml` accepts an optional `judged_as` on a theorem or lemma claim: the comparator theorem that judges it when the Challenge theorem is not named after the `decl`. It replaces the naming rule for that claim everywhere a comparator name is credited (`receipt check`, the claims ledger, `--coverage`, R11, the page), and is checked: one claim per name, a configured name, a declared `decl` ([explicit mapping](../comparator.md#how-a-theorem-name-maps-to-a-claim)). Proposal 0006 (accepted). lean-pkg 0.13.0 and older refuse the key. | Nothing if your Challenge names follow the naming rule. Otherwise add `judged_as` to each judged claim, require this release, and gate the new commit (`claims.yaml` is bound to the receipt commit). |

PRs #257 (a Codespaces dev container for the π-λ tutorial), #258 (the
lts-2026.10 stage 0 matrix results, as docs) and #259 (lts-2026.10
declared, as docs) were read for this record; none needs anything from a
package author.
