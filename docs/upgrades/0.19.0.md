# Upgrading to 0.19.0 (from 0.18.0)

The changes merged after 0.18.0 that a package author should know about.
The machine-readable record is [0.19.0.yaml](0.19.0.yaml). This page is
filled in as pull requests merge, until 0.19.0 is cut. `lean-pkg doctor
--upgrade-from 0.18.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.
The name 0.19.0 is provisional: the release is named by what it holds
(RELEASING.md, "When to tag"), and the record is renamed with it.

Nothing so far is required of a package author.

PR #277 (docs: [recovering an interrupted
campaign](../receipts.md#recovering-an-interrupted-campaign-read-only) and
[will my old receipts still
pass?](../receipts.md#will-my-old-receipts-still-pass-upgrade-impact), a
read-only composition of `git`, `receipt check --json`,
`receipt slurm --check --json`, `squeue` and `sacct`, with a table that maps
each failing check of `receipt check` to *passes now*, *needs restoration
only* or *needs a new run*) was read for this record; it changes nothing for
a package author.

PR #278 (release tooling: `make release-version` derives the next version
from this record and the CHANGELOG, `make cut-release` refuses any other,
`make changelog` checks that a docs-only pull request's entry is not under
`### Added`, and cut-release names this record for the version it cuts)
was read for this record; it changes nothing for a package author.
