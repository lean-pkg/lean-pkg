# Upgrading to 0.17.0 (from 0.16.0)

The changes merged after 0.16.0 that a package author should know about.
The machine-readable record is [0.17.0.yaml](0.17.0.yaml). This page is
filled in as pull requests merge, until 0.17.0 is cut. `lean-pkg doctor
--upgrade-from 0.16.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.

Nothing so far is required of a package author, except to re-render a page
whose result statements open with `let`, `letI`, `have` or `haveI`:

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `statement-let-boundary` | #273 | The Lean statement the verification page shows beside a result (`lean_scan.statement`, also used through an umbrella Challenge) stopped at the first `:=` outside brackets, so a statement with a top-level `let`, `letI`, `have` or `haveI` (`theorem t : let n : Nat := 1; n = 1`) was cut to its binder, without the bound value and the conclusion (lab field report). Each such opener now owns one later `:=` (its value) and the proof starts at the next free one. A statement the scanner cannot read with certainty (a `by`, `calc` or `do` outside brackets before the proof, or a `\| pattern =>` line with no `match` or `fun` before it) is refused: the page says the statement could not be read reliably and links the file instead of showing a prefix. | Nothing for most package authors. A package whose result statements open with `let`, `letI`, `have` or `haveI`: rerun `page NAME --write` to replace the truncated statement. |

PR #272 (docs: [filling missing dependency artifacts from a pinned
donor](../receipts.md#filling-missing-dependency-artifacts-from-a-pinned-donor)
and a [transport checklist for every declaration
form](../extract.md#checklist-after-a-namespace-or-import-transport-every-declaration-form-one-combined-import))
was read for this record; it changes nothing for a package author.
