# Upgrading to 0.26.0 (from 0.25.0)

The changes merged after 0.25.0 that a package author should know about.
The machine-readable record is [0.26.0.yaml](0.26.0.yaml). This page is
filled in as pull requests merge, until 0.26.0 is cut. `lean-pkg doctor
--upgrade-from 0.25.0` prints the mechanical part, and the
[design](../design/upgrade-preflight.md) explains how the record is used.
The name 0.26.0 is provisional: the release is named by what it holds
(RELEASING.md, "When to tag"), and the record is renamed with it.

Nothing so far is required of a package author; a `coverage.yaml` that uses the new
`conclusion` keys needs this release or later.

## Nothing required

| Entry | PR | What changed | What to do |
|---|---|---|---|
| `types-namespace-relative-decl` | #418 | `comparator config --challenge-from-type` / `--emit-script` asks Lean for the full name of a claim `decl` written relative to its namespace, read from the claim's file at HEAD, instead of failing with "unknown constant" ([comparator](../comparator.md#pre-filling-statements-from-the-elaborated-types)). | Nothing. Re-run the pre-fill for claims that stayed TODO; write full names in `claims.yaml` for them to be credited as covered. |
| `install-from-pypi` | #421 | lean-pkg is on PyPI from 0.25.0; the install docs say `pipx install lean-pkg` instead of the Git URL. | Nothing. To have pipx follow PyPI releases instead of Git, run `pipx uninstall lean-pkg && pipx install lean-pkg` once. |
| `recommend-notice-pypi` | #422 | The upgrade notice of [`registry recommend`](../commands/registry-recommend.md) and doctor's `recommended` line say `pipx install --force 'lean-pkg==X.Y.Z'` for a recommendation of 0.25.0 or later; older ones keep the git-tag route. | Nothing. A script that matched the notice's Git URL also matches `lean-pkg==X.Y.Z`. |
| `coverage-conclusion-strength` | #419 | A paper row of `coverage.yaml` may say that its Lean conclusion is weaker than the paper's, or a special case of it: `conclusion: weaker` or `special-case`, with a one-line `conclusion_scope` ([proposal 0010](../proposals/0010-coverage-conclusion-strength.md)). The page then says "Verified: a weaker statement." or "Verified: a special case." with a **Conclusion.** line, never the bare "Verified.", and counts them in the header ([the page](../page.md#a-weaker-conclusion-or-a-special-case)). | Nothing for files without the keys: they render as before. A file that uses the keys needs this release or later (an older lean-pkg refuses them): raise the CI pin first. |
| `status-recorded-commit` | #423 | [`status`](../commands/status.md)'s `scope.gate` gains `recorded_commit` and `commit_source`; a host without the checkout sees the commit the gate recorded, labelled as not checked against a checkout, instead of "unreadable". | Nothing. Read `scope.gate.recorded_commit` instead of `history[-1].commit`. |
